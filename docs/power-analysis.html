02 Issues found, ranked by impact

1. Power profile pinned to “Performance” — even on battery HIGH STATUS: fixed ✓

PPD ActiveProfile = performance, so tuned runs throughput-performance-bazzite while discharging: CPU boost forced on (cpb_boost=enabled), game-oriented sysctls (vm.swappiness=180…), and audio codec never sleeps (snd power_save = 0). tuned-ppd only remaps balanced/power-saver for battery — performance is never downshifted on AC removal. The ASUS quiet EC profile (→ EPP power) partially compensates; the two stacks are working against each other.

Fix — immediate (syncs GNOME Quick Settings)
sudo busctl --system set-property net.hadess.PowerProfiles \
  /net/hadess/PowerProfiles net.hadess.PowerProfiles \
  ActiveProfile s balanced
Fix — automatic (AC = performance, battery = battery-tuned)

ppd.conf already has a [battery] section, and tuned-ppd enforces an injective map (no two PPD profiles → same tuned profile). Bazzite already uses balanced-battery-bazzite for balanced, so battery performance must map to the plain balanced-battery profile (same EPP/panel-savings/audio tuning, minus the Bazzite extras).

# map battery+performance to the plain balanced-battery profile:
sudo sed -i 's/^performance=balanced-battery-bazzite$/performance=balanced-battery/' /etc/tuned/ppd.conf
# (if you never added the line, append it inside [battery] instead:
#  echo "performance=balanced-battery" | sudo tee -a /etc/tuned/ppd.conf)
sudo systemctl restart tuned-ppd

2. Panel fixed at 180 Hz — main driver of the ~7 W GPU idle draw HIGH STATUS: done ✓

DCN + eDP link + panel at max refresh, with Panel Self-Refresh rarely engaging over an animated desktop. This is the largest available in-use saving.

Status (2026-09-05): fixed 60 Hz is now enforced automatically on battery via the user service panel-refresh.service (~/.local/bin/panel-refresh, polls every 10 s): battery → 2560x1600@60.000, AC → restores 2560x1600@180.000+vrr. Measured −≈3 W (12.6–13.3 W → 9.5–9.7 W on the same in-use desktop).

  • Manual: Settings → Displays → 60 Hz when unplugged. Typical saving on this class of panel: −1.5…−4 W.
  • Optional automation: systemd service reacting to BAT0 power-source events calling gnome-randr to flip refresh rate. Can be baked into this image repo (files/system/ + justfile).
  • Alternative: enable VRR/adaptive-sync so the panel can drop below 180 Hz — less deterministic than a fixed 60 Hz on a static desktop.

3. Verify GPU memory clock actually downclocks MEDIUM — verify verified ✓

On Strix Halo, pinned UCLK/MCLK is a classic idle-power bug (LPDDR5X at full rate draws several watts). The 128 GB GTT carve-out kargs do not pin clocks by themselves, but high refresh + large framebuffer allocations can. Requires root:

sudo cat /sys/kernel/debug/dri/1/amdgpu_pm_info | grep -iE "uclk|sclk|mclk"

If UCLK/MCLK shows max while idle, that is a separate real problem to chase (and the amdgpu.gttsize=131072 / ttm.pages_limit kargs become suspect).

Result (2026-09-05): MCLK = 400 MHz, SCLK = 704 MHz at idle — clocks downclock correctly, no pinned-memory issue. Average SoC power 7.8 W (incl. CPU) at ~10 % GPU load. Nothing to chase here.

Verified: fwupd exposes no “System Firmware” (UEFI capsule) device on this laptop — ASUS does not publish the GZ302EA BIOS on LVFS, so fwupdmgr update can not update the BIOS here. Method — ASUS EZ Flash 3 (no Windows needed, recommended)

  1. Download from ASUS support: ROG Flow Z13 (2025) GZ302 → Driver & Tools → BIOS & FIRMWARE → select model GZ302EA → “BIOS for ASUS EZ Flash Utility” Version 314 (14.25 MB). Direct page: rog.asus.com/laptops/rog-flow/rog-flow-z13-2025/helpdesk_bios/
  2. Prepare USB: format a USB stick FAT32, extract the ZIP, copy GZ302EAAS.314 (the .cap) to its root.
  3. Enter BIOS: shut down, plug in the AC adapter, press F2 repeatedly at power-on (or Esc → Setup).
  4. Flash: Advanced Mode (F7) → Tool → ASUS EZ Flash 3 Utility → select the file from the USB stick → confirm. Takes ~5 min — do not power off or unplug.
  5. Verify: after reboot check sudo dmidecode -s bios-version → expect GZ302EA.314.

Optional peripheral firmware (Windows-only tools)

The same ASUS page hosts ROG PD Firmware (USB-C PD/PPS charging behavior), Keyboard (LED issues) and Light Bar updaters — all Windows executables. None are available from Linux. Only relevant if you observe charging quirks or keyboard/LED bugs.

⚠ Precautions:
  • AC power mandatory; never interrupt a flash (brick risk).
  • 314 shipped 2026-08-31 and ASUS publishes no release notes — skim r/FlowZ13 / the ROG forum for 314 reports first; GZ302EA has had problematic BIOS releases before.
  • BIOS updates are orthogonal to Bazzite: ostree/kernel/boot config are untouched; nothing to reconfigure afterwards.
